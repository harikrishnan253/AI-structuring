# Offline Calibration & Evaluation Pipeline

Operational reference for the offline tooling that calibrates the document structuring pipeline without requiring LLM API calls.

**Scope:** Rule learning, semantic artifact build, generalization evaluation, and runtime integration.
**Not covered here:** Live pipeline execution, Flask/Celery setup, DOCX processing.

---

## Architecture Overview

```
backend/data/ground_truth.jsonl          (corpus: 30 docs, ~11k labelled entries)
         |
         |-- [Phase 1] build_semantic_knowledge.py
         |       |
         |       +-> backend/data/tag_semantics_knowledge.json    (zone-tag priors)
         |       +-> backend/data/tag_transition_priors.json      (sequential transitions)
         |       +-> backend/data/style_alias_candidates.json     (publisher aliases)
         |
         |-- [Phase 2] processor/rule_learner.py --train
         |       reads: ground_truth.jsonl + artifact JSONs (optional)
         |       writes: backend/data/learned_rules.json
         |
         |-- [Phase 3] tools/eval_generalization.py
                 reads: ground_truth.jsonl + learned_rules.json + artifact JSONs (all optional)
                 writes: stdout report (+ optional --report-file)
```

**Runtime classifier** reads only `learned_rules.json` (optional). It never reads the corpus or artifact files.

## Phase 1: Build Semantic Artifacts

**Script:** `backend/tools/build_semantic_knowledge.py`
**Status:** ✅ Implemented and run (2026-02-27). Artifacts exist in `backend/data/`.

### Standard run:
```bash
python tools/build_semantic_knowledge.py
```
Defaults: min-support=3 (bigrams), min-alias-confidence=0.70.

### Key flags:
```
--min-support INT          minimum bigram count for transition priors (default: 3)
--min-alias-confidence F   minimum confidence to include alias candidate (default: 0.70)
--dry-run                  compute but do not write files
--ground-truth PATH        override ground_truth.jsonl path
--report-out PATH          override Markdown report path
--log-level LEVEL          DEBUG / INFO / WARNING (default: INFO)
```

### Outputs:
| Artifact | Size | Content |
|----------|------|---------|
| `tag_semantics_knowledge.json` | ~285 KB | zone_tag_priors, tag_families, positional/depth/marker/table/reference semantics |
| `tag_transition_priors.json` | ~58 KB | global_transitions (193 source tags, min_support=3) |
| `style_alias_candidates.json` | ~47 KB | 158 candidates (118 existing aliases validated, 40 new proposals) |
| `outputs/corpus/tag_rationale_report.md` | ~8 KB | Human-readable summary with tables |

## Phase 2: Train Rules

**Script:** `backend/processor/rule_learner.py`
**Run from:** `AI-structuring/backend/`

### Standard run (with holdout + semantic enrichment):
```bash
python processor/rule_learner.py --train
```
Defaults: holdout=20%, seed=42, min-support=10, min-confidence=0.8, semantic=on.

### Key flags:
```
--train                     required to train; otherwise only --report prints existing rules
--report                    print learned rule stats after training
--report-file PATH          save report to file

--holdout / --no-holdout    enable/disable holdout validation (default: on)
--holdout-fraction FLOAT    fraction of docs held out (default: 0.2)
--holdout-seed INT          RNG seed for reproducibility (default: 42)

--no-semantic               disable semantic artifact enrichment
--semantic-knowledge PATH   override path for tag_semantics_knowledge.json
--semantic-transitions PATH override path for tag_transition_priors.json

--min-support INT           minimum corpus occurrences for a rule to be included (default: 10)
--min-confidence FLOAT      minimum rule precision on training data (default: 0.8)

--log-level LEVEL           DEBUG / INFO / WARNING (default: INFO)
```

### Outputs:
- `backend/data/learned_rules.json` — rule list + tag_stats + optional metadata block
- Stdout report (or `--report-file`) with top-50 rules, holdout evaluation, semantic enrichment counts

### Holdout report sections to check:
```
HOLDOUT EVALUATION
  total:    N holdout paragraphs
  covered:  X (coverage %)
  correct:  Y (precision % of covered, accuracy % of total)

  Per-tag breakdown:
  TAG          TP    FP    FN    Prec   Rec
  ...
```

Low coverage (< 30%) is normal for the first run with a small corpus. Low precision (< 70%) on covered entries is a signal to raise `--min-confidence`.

### Semantic enrichment section:
```
SEMANTIC ENRICHMENT
  N candidate rules added from semantic artifacts
  [semantic] rules are marked in the top-50 list
```

Zero enriched rules when artifact files are missing — expected until Phase 1 is built.

## Phase 3: Evaluate Generalization

**Script:** `backend/tools/eval_generalization.py`
**Run from:** `AI-structuring/backend/`
**No LLM API required.**

### Standard run (book-level holdout, all modes except retriever):
```bash
python tools/eval_generalization.py
```

### Common invocations:
```bash
# Publisher-level holdout, all modes
python tools/eval_generalization.py --split publisher --modes all

# Book-level, specific modes only
python tools/eval_generalization.py --modes baseline alias semantic rules

# Save report to file
python tools/eval_generalization.py --report-file outputs/eval_$(date +%Y%m%d).txt

# Larger holdout, different seed
python tools/eval_generalization.py --holdout-fraction 0.3 --seed 7

# Debug
python tools/eval_generalization.py --log-level DEBUG
```

### All flags:
```
--split {book,publisher}      holdout strategy (default: book)
--holdout-fraction FLOAT      fraction held out (default: 0.2)
--seed INT                    RNG seed (default: 42)
--modes MODE [MODE ...]       subset of modes to run; "all" includes retriever (default: baseline alias semantic rules)
--min-alias-confidence FLOAT  minimum confidence for alias candidates (default: 0.70)
--no-train-rules              skip auto-training rules if learned_rules.json is missing
--report-file PATH            write report to this path in addition to stdout
--log-level LEVEL             DEBUG / INFO / WARNING (default: INFO)
```

### Ablation modes (additive — each mode builds on the previous):

| Mode | What is added | Requires |
|------|---------------|----------|
| `baseline` | `normalize_tag(gold_tag)` only | nothing |
| `alias` | style alias lookup from `style_alias_candidates.json` | artifact file (optional) |
| `semantic` | zone-prior and transition-prior hints | artifact files (optional) |
| `rules` | `apply_rules()` from `learned_rules.json` as primary | learned rules (optional) |
| `retriever` | TF-IDF grounded retriever over full ground_truth | **[LEAKAGE — dev only]** |

### Metrics explained:

| Metric | Description | Normal range |
|--------|-------------|--------------|
| `accuracy` | % correct canonical tags on holdout | 70–90% for `rules` mode |
| `zone_violation` | % predictions invalid for their zone | < 5% is healthy |
| `list_depth` | accuracy on BL2/BL3/NL2/NL3 entries | often lower; < 60% indicates list handling gaps |
| `table_sem` | accuracy on TABLE-zone entries (aggregate) | 60–85% typical |
| `ref_accuracy` | accuracy on BACK_MATTER entries | 75–90% typical |
| `txt_fallback` | % predictions that resolved to TXT or TXT-FLUSH | < 20% desired |
| `unmapped_rate` | % entries with no canonical mapping in allowed_styles | should be < 2% |
| `invalid_tag_rate` | % predictions not in `allowed_styles.json` | should be < 1%; proxies Stage 4.5 workload |
| `structure_guard_fail_rate` | % list/heading gold entries where predicted tag changes structural category (list↔non-list or heading↔non-heading) | should be < 3%; proxies Structure Guard failure risk |

`n/a` in a cell means no holdout entries existed for that category with the current split.

**TABLE SEMANTICS DETAIL section** (appended to report): per-gold-tag accuracy breakdown for table-semantic entries (zone=TABLE or gold in table styles). Tags T, T1, T2, T4, TFN, TSN listed first; remaining tags alphabetically. Gate aligns with `table_sem` metric for consistency.

**`structure_guard_fail_rate` note:** This is a simulation metric computed from flat holdout predictions; it does not account for document-level sequential context. Actual Structure Guard outcomes depend on paragraph-ordering that is not available during holdout evaluation.

## Holdout Strategies

### Book-level (default)
- Random sample of complete documents held out.
- Maintains within-publisher diversity in both train and holdout sets.
- Good for measuring overall generalization.

### Publisher-level (`--split publisher`)
- All documents from randomly selected publishers are held out.
- Tests whether the pipeline generalizes to unseen publisher styles.
- More conservative; expect lower accuracy than book-level.
- Use this before deploying to a new publisher family.

Both strategies use seeded RNG (`--seed`) for reproducibility. Use the same seed when comparing runs.

---

## Data Leakage Rules

1. **Never run `retriever` mode as a production benchmark.** It reads the full `ground_truth.jsonl` including holdout documents. Results are contaminated. Use it only for an upper-bound reference.
2. **Artifact files are built from the full corpus.** If `tag_semantics_knowledge.json` is built from the full corpus (including holdout docs), the `semantic` and `alias` ablation modes have mild leakage. For a strict evaluation, build artifacts from the training split only.
3. **`learned_rules.json` must be trained on the same split.** If `learned_rules.json` was trained on the full corpus, `rules` mode results on a holdout are optimistic. Use `rule_learner.py --train` with the same `--holdout-seed` before running `eval_generalization.py`.
4. **`prev_tag` rules cannot fire at eval time without sequential context injection.** `apply_rules()` calls `extract_features(text, metadata)` internally; it does not inject `prev_tag` from metadata. Transition-prior rules in `learned_rules.json` will have zero coverage in the `rules` mode predictor.

## Runtime Integration

Only `learned_rules.json` flows from the offline pipeline into the live classifier:

```
learned_rules.json
       |
       v
backend/processor/rule_learner.py  load_rules()
       |
       v
backend/processor/classifier.py    apply_rules() called before LLM eligibility check
```

The classifier never reads `ground_truth.jsonl`, artifact JSONs, or `eval_generalization.py` outputs.

When `learned_rules.json` is missing:
- Default: logs an INFO once, continues without rules (controlled by `REQUIRE_LEARNED_RULES=false`)
- Strict: set `REQUIRE_LEARNED_RULES=true` to fail hard on missing rules

---

## Operational Toggles

### `REQUIRE_LEARNED_RULES`

| Value | Behaviour |
|-------|-----------|
| `false` (default) | Missing `learned_rules.json` is silently tolerated; logged once at INFO then suppressed |
| `true` | Missing `learned_rules.json` raises a hard failure at classifier startup |

### `ENABLE_GROUNDED_RETRIEVER`

| Value | Behaviour |
|-------|-----------|
| `false` (default) | Classifier never loads `ground_truth.jsonl`; production default; evaluation is uncontaminated |
| `true` | Classifier builds a TF-IDF index over `ground_truth.jsonl` at startup and injects similar labeled paragraphs into the LLM prompt as grounded examples |

**Risk when enabled:** The in-memory TF-IDF index is built once at startup and not refreshed if `ground_truth.jsonl` is updated while the service is running. Restart the service after any corpus update (see NGL-004 in KNOWN_ISSUES.md).

**Do not use `ENABLE_GROUNDED_RETRIEVER=true` as a production default.** It creates a corpus dependency in the runtime path, prevents clean offline/online separation, and makes holdout evaluation contaminated for that service instance.

### `GROUNDED_RETRIEVER_MODE`

Controls the behaviour of the grounded retriever when `ENABLE_GROUNDED_RETRIEVER=true`.

| Value | Behaviour |
|-------|-----------|
| `off` | Retriever is loaded but not invoked (no-op; useful for staged rollout) |
| `prompt_examples` (default when enabled) | Top-k similar paragraphs from ground-truth injected as few-shot examples in the LLM prompt |
| `invalid_tag_fallback` | Retriever invoked only when the primary classifier returns a tag not in `allowed_styles.json`; provides a grounded second-pass suggestion |

`GROUNDED_RETRIEVER_MODE` is ignored when `ENABLE_GROUNDED_RETRIEVER=false`.

## Re-Training Checklist

Run this sequence when the corpus is updated (`ground_truth.jsonl` changes):

1. **Rebuild semantic artifacts:**
   ```bash
   python tools/build_semantic_knowledge.py
   ```
2. **Retrain rules:**
   ```bash
   python processor/rule_learner.py --train --report --report-file outputs/rules_report.txt
   ```
3. **Evaluate generalization:**
   ```bash
   python tools/eval_generalization.py --split book --report-file outputs/eval_book.txt
   python tools/eval_generalization.py --split publisher --report-file outputs/eval_pub.txt
   ```
4. **Check holdout accuracy delta vs. previous run.** If `rules` mode accuracy drops > 5 pp, investigate which tag categories regressed before deploying the new `learned_rules.json`.
5. **Commit `learned_rules.json`** (and artifact JSONs if rebuilt) to version control.

## Known Limitations

- `prev_tag` transition rules are learned but never fire at runtime (see NGL-001 in KNOWN_ISSUES.md).
- Publisher-level holdout requires at least 5 publishers to produce meaningful splits with the default 20% fraction.
- eval_generalization uses gold `prev_canonical_tag` for the semantic predictor's transition check (not predicted), which avoids error cascading but slightly overestimates the benefit of transition priors.
- `structure_guard_fail_rate` is a flat-holdout simulation metric. It does not reproduce the document-sequential context that the real Structure Guard uses, so it may undercount or overcount actual failures for zone-boundary paragraphs.
- Grounded retriever TF-IDF index is stale after corpus updates until service restart (see NGL-004 in KNOWN_ISSUES.md).
